# 낚시월드 게임 바이블

이 문서는 채팅 밖에서도 유지되는 **게임 결정의 기준 문서**다. 게임 코드와 별도로 세계관·기획·아트·밸런스·진행 조건을 기록한다. 각 내용은 `확정`, `미정`, `구현 상태`, `폐기`를 분리한다. 새 결정이 생기면 기존 항목을 조용히 덮지 말고 날짜와 변경 이유를 기록한다.

## 최신 결정을 읽는 순서
1. 가장 최근 사용자 명시 결정. 특히 `WORK_STATE.json`이 가리키는 현재 작업의 결정 기록.
2. 이 문서의 결정표와 관련 세부 기획 문서.
3. 실제 최신 Release와 최신 작업 브랜치 코드. 코드는 구현 여부의 근거이지 기획 승인 근거가 아니다.
4. 과거 handoff, 구버전 기획, 채팅 요약.

불일치하면 최신 명시 결정을 우선하고, 구현과 다른 부분은 버그/미구현으로 기록한다. 모르는 내용을 사용자에게 다시 확인하기 전에 이 문서·최신 handoff·현재 코드·과거 기획 자료를 먼저 찾는다. 동일 질문을 다시 하지 않는다.

## 미정으로 유지할 항목

- 각 지역 메인 번들의 어종, 등급, 마릿수 및 완수 요구량. 사용자가 직접 고르기 전까지 `준비 중`; 이를 추측해 구현하거나 잠금 해제하지 않는다.
- 주인 게이지가 낚시 몇 회/어떤 결과에서 얼마나 차는지, 게이지 UI와 지역별 초기 진행률. 기존 기획·코드에서 먼저 찾고도 정의가 없다면 묶어서 질문한다. 단, 모든 파츠 착용 조건/100% 후 다음 물고기/놓치면70%/잡으면0%는 확정.
- 20종의 입질/등급 확률, 판매가, 무게 및 전투 수치. 승인된 길이 표만 수치 확정으로 취급한다.
- 차원관리국 이야기의 장별 서사, NPC 대사와 미구현 지역 세부.

## 표현/아트 원칙

- 따뜻하고 아기자기한 16비트 도트, 세로 모바일, 선명한 픽셀 묶음과 제한된 명암.
- 낚시 플레이가 화면 중심. 저수지와 비슷한 플레이 구도(왼쪽 앉는 자리/수면/수중 플레이 공간)는 유지하되 지역 배경과 바닥은 분명히 다르게.
- 계곡 사용자가 선택한 상세 배경을 보존. 캐릭터가 앉을 왼쪽 낚시 자리는 실제 게임에서 낮게 배치하고 너무 길게 만들지 않는다. 배경에 캐릭터/의자/구름/폭포가 구워져 있으면 안 된다. 기존 의자·캐릭터를 재사용한다.
- 구름은 하늘 마스크 내 별도 레이어, 역폭포는 수면에서 위쪽 섬으로 올라가는 별도 애니메이션, 수면은 얕은 잔물결/반사 별도 레이어, 수중 빛도 별도 레이어. 수심색과 지형은 선택한 정적 배경을 보존한다.
- 저수지 건물/바닥/배경을 다른 낚시터에 복사하지 않는다. 배경을 임의 재생성·대체하지 않는다.
- 승인 범위를 벗어난 유료 PixelLab 생성은 진행하지 않는다. 생성 규칙은 `docs/FISH_ART_RULES.md` 우선.

## 유지해야 할 핵심 플레이/경제

- 별(어종 난도)과 개체 등급은 독립. 신화 개체라고 최대 길이를 보장하지 않는다.
- 같은 낚싯대 업그레이드/파츠 체계는 낚싯대 1개 + 찌·바늘·줄·릴 4파츠. 파츠 부족은 가능한 별의 상한을 제한. 별5 주인은 게이지 방식으로만 등장.
- 가방은 무게 용량, 넘치는 큰 물고기 1마리는 어깨에 메고 돌아올 수 있음. 현장 판매 대신 마을에서 판매/전시/손질을 선택.
- 수족관은 오프라인 수익, 기존 사용자 세이브와 업데이트 안전성을 보존.
- 자세한 기존 세부 밸런스는 `docs/REGIONAL_SHOP.md`, 최신 소스·Release 검증은 `docs/RELEASE_068_VERIFICATION.json`을 참고하되 이 문서의 최신 사용자 결정을 우선한다.

## 기록 규칙

새 결정은 이 표에 날짜, 영역, 정확한 규칙, 출처/상태를 추가한다. 취소/대체된 규칙은 지우지 말고 `폐기`로 남긴다. 구현 코드는 별도 `구현 상태`로 적는다. 모든 기획 결정을 코드가 반영했다고 추정하지 않는다.
