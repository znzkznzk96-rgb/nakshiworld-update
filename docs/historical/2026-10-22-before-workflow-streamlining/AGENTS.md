# 낚시월드 에이전트 작업 규칙

- 시작 시 START_HERE.md, docs/PROJECT_INSTRUCTIONS.md, docs/CONTINUE_HERE.md, docs/GAME_BIBLE.md, HANDOFF.md, WORK_STATE.json, CHANGELOG.md 및 실제 최신 Release를 읽는다. 필요한 작업 브랜치도 확인한다.
- 한국어로 간결하게 답하고 실제 확인·이전 보고·추정을 구분한다.
- 요청 범위와 승인된 UI/그림/밸런스를 지킨다. 앱 삭제/데이터 초기화를 문제 해결 수단으로 사용하지 않는다.
- 의미 있는 단계 및 완료 보고 전 코드/리소스와 HANDOFF/WORK_STATE를 동일 커밋으로 원격 저장한다. GitHub 연결 또는 checkpoint 도구를 사용하고 원격 SHA를 확인한다.
- 중간 저장은 work/* 브랜치에서만 수행한다. main과 codex/r2-migration의 game/automation 변경은 배포 트리거이므로 중간 저장용으로 사용하지 않는다. 작업 시작 시 실제 workflow 조건이 달라졌는지도 확인한다.
- HANDOFF에 목표, 완료/남은 작업, 실패, 테스트, 다음 단계, 배포 여부를 남긴다. 내용 변경 없이 '완료'만 기록하지 않는다.
- 공개 패치 전 CHANGELOG/인수인계를 갱신한다. 버전·커밋·소스 ZIP·PCK·manifest·크기·해시를 확인하고 게시 후 인수인계에 실제 결과를 갱신한다. 휴대폰 적용은 사용자 확인과 구분한다.
- 저장소 game/은 전체 프로젝트가 아니다. 최신 Release 전체 소스를 기준으로 복원한다. 새 에셋과 삭제/이름 변경까지 재현 가능하게 보존하며, 현재 복원 workflow가 삭제를 반영하지 못하면 배포 전에 수정·검증한다.
- 토큰/비밀번호/키스토어/실제 사용자 세이브를 커밋하지 않는다. 테스트 데이터 경로를 분리한다.
- 이미 승인된 작업은 재승인 없이 진행하되 사용자가 배포/수정을 금지하거나 중단하면 따른다.
- 로컬 또는 원격 저장 실패는 숨기지 않는다. 모든 대화 내용이 자동 공유되거나 저장되지 않은 작업이 복구된다고 주장하지 않는다.

## 모든 낚시터 물고기 제작 — 필수
- 유료 이미지 호출 전 docs/FISH_ART_RULES.md를 읽고 준수한다. 외형은 승인 시안, 색감·도트·명암은 실제 저수지 원본. 임시 컬러 시안을 API 초기/스타일/색 입력으로 그대로 넣지 않는다.
- 어종별 고유색과 참조 역할을 먼저 기록한다. 금빛 붕어 하나를 전 어종 공통 강한 참조로 쓰지 않는다.
- 첫1종부터 실제 저수지 원본과 비교 검수. 한 종 생성→검수→다음 종, 유료 요청 최대1개. 첫 결과 또는 중간 결과가 부적합하면 후속 호출 중단. 실패를 알면서 대량 생성 금지.
- 어종당1회 제한·비용을 지키고 자동 재시도하지 않는다. 최초 색감 거절본은 실패 기록이며 적용/참조 금지. 이후 확정 모음은 디자인 선택본으로, 실제 게임 연결·검수·배포 여부는 최신 HANDOFF/WORK_STATE에서 확인한다. 추가 유료 생성은 승인 없이 하지 않는다.

## 채팅 연속성 및 결정 원본 — 필수
- 새 채팅은 START_HERE.md → docs/CONTINUE_HERE.md → docs/GAME_BIBLE.md → WORK_STATE.json → 현재 작업 브랜치 HANDOFF.md를 먼저 읽는다. 첨부를 다시 요구하거나 사용자가 이미 답한 질문을 반복하지 않는다.
- 모든 지속성 있는 시스템/설정/세계관/화면/아트/밸런스 결정은 사용자가 확정/변경한 즉시, 코드 수정이 없어도 같은 작업에서 `docs/GAME_BIBLE.md`에 상태(확정/미정/구현/폐기), 날짜와 근거를 함께 기록한다. 구현은 이 기록 이후 시작한다. 관련 변경물·HANDOFF·WORK_STATE를 `work/*`에 원격 checkpoint하고 새 SHA 및 파일 내용을 재확인한다. 원격 저장이 모두 실패하면 미저장 대기로 표시해 사용자에게 알리고 다음 채팅에서 이미 저장된 것처럼 취급하지 않는다. 문서가 상충하면 최신 사용자 명시 결정을 기준으로 정정하고 변경 이력을 보존한다. 코드 구현만 보고 기획 승인으로 추정하지 않는다.
- `docs/CONTINUE_HERE.md`는 다음 채팅이 바로 실행할 인수인계 경로이며, `HANDOFF.md`는 현재 작업의 상세 진행 기록, `WORK_STATE.json`은 현재 작업 포인터다. 이 역할을 합치거나 수동 ZIP 첨부에 의존하지 않는다.
- 원격 저장 실패를 만나면 허용된 GitHub 연결/API 등 다른 원격 경로를 시도한다. 전부 실패할 때만 사용자에게 알리고 로컬에만 있는 구체적인 미저장 결과를 밝힌다.
