# 다운로드·프록시 오류에서 이어하기 — 2026-11-06

## 확인된 범위
사용자가 새 Codex의 “네트워크 프록시 연결 오류로 코드 다운로드 불가, GitHub 문서 조회 가능, 수정/배포 없음” 보고를 전달했다. 이 보고만으로 실패 URL·HTTP 코드·프록시 설정·전체 네트워크 차단 여부는 알 수 없다. 이전 인수인계 검증은 이전 Work 환경의 clone과 원격 문서 저장에 한정된다. 새 Codex의 clone·Release 다운로드·도구 인증을 검증한 것이 아니다.

## 중단 전에 할 일
1. 로컬에 이미 체크아웃된 프로젝트가 있는지 cwd, git status, git remote, project.godot 존재를 확인한다. 기존 수정은 보호한다. 새 환경에 이전 scratch 경로가 있다고 가정하지 않는다.
2. 실패를 구분한다: git clone/fetch, Release ZIP, Release 리다이렉트 목적지, Godot 다운로드 중 어느 단계인지. 정확한 명령·비밀정보를 제거한 stderr·HTTP 상태를 기록한다. 프록시 주소의 사용자명/비밀번호와 인증 헤더를 출력하지 않는다.
3. 연결된 GitHub 도구가 있다면 원격 ref → commit/tree → 필요한 파일을 SHA에 고정해 읽는다. 문서만 읽지 말고 필요한 GDScript·복원 스크립트도 읽어 코드 검토/수정안을 진행할 수 있다. 실제 쓰기 권한이 있으면 기존 Git Data API checkpoint 절차로 work/*에 저장하고 SHA/내용을 확인한다. 그 도구가 새 Codex에 없으면 있는 척 호출하지 않는다.
4. GitHub 파일 조회는 전체 Release ZIP 다운로드를 대체하지 않는다. 이 프로젝트의 game/은 일부 overlay다. 전체소스 ZIP과 리소스가 없으면 실행·전체검사·PCK 빌드 완료를 주장하지 않는다. binary는 지원 도구의 base64 blob을 원래 바이트로 복원하고 SHA를 확인한다. 텍스트 응답에 바이너리를 억지로 넣지 않는다.
5. 환경에서 허용된 다운로드/첨부 전송 경로가 있으면 v1.06 game-source.zip을 사용한다. 기준 크기·SHA는 CODEX_HANDOFF에 있다. URL만 다시 주는 것은 프록시 문제 해결이 아니다. 네트워크 정책/프록시를 임의 우회하거나 인증을 제거하지 않는다.
6. 허용 경로가 모두 막혔다면 차단된 단계/파일과 가능한 작업을 구분해 보고한다. 네트워크를 사용자가 설정해야 하는 경우 실제 오류를 근거로 필요한 접근만 요청한다. 사용자에게 프로젝트 전체를 다시 설명하게 하지 않는다.

## 독립적으로 가능한 작업
GitHub 조회가 가능한 동안 WORK_STATE/HANDOFF/현재 SHA 확인, 손상 PNG의 기록 해시 대조, 관련 코드·테스트 검토, 정확한 복구 및 검사 계획 작성은 가능하다. 전체소스 미확보를 이유로 승인된 아트 재생성이나 옛 ZIP 덮어쓰기를 하지 않는다.

## 별개의 두 차단
- 환경 차단: 새 Codex 프록시 오류. 원인/해결 여부 미확인.
- 프로젝트 차단: 1.07 배경 PNG의 디코드 실패와 승인 SHA 불일치. 이전 인수인계에서 직접 확인.
네트워크가 복구돼도 PNG 문제는 별도 복구해야 한다. 이번 문서 보완은 어느 문제도 해결 완료했다는 뜻이 아니다.
