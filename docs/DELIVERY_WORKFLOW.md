# 개발 검사와 배포 절차

2026-11-13 사용자 승인. 검사를 생략하지 않고 불필요한 전체 반복을 줄인다.

## 개발 중

- 최신 Release 전체 소스+work overlay/삭제 명세를 기준으로 필요한 수정과 영향범위 관련검사를 수행한다. 같은 기준의 도구/import 캐시는 유효하면 재사용한다.
- 작은 코드·문서·도구 저장은 전체 CI를 자동 실행하지 않는다. 화면 수정은 해당 실제 화면을 먼저 확인한다.
- 세이브·공통 시스템 변경에는 필수 전체 검사를 요청한다. 배포 여부와 별개이며 실제 사용자 세이브를 쓰지 않는다.

## 필수 전체 검사 요청

- 배포 승인 후 최종 버전·업데이트 우편·관련검사를 먼저 확정한다. `automation/release.json` 변경 push가 기존 verify-work 전체 검사/native/PCK/후보 생성을 시작한다.
- 같은 버전에서 검사를 다시 요청하거나 세이브/공통 변경을 검사할 때는 다음 명령으로 요청 파일을 만들고 work/*에 저장한다. source는 확인한 현재 원격 work head이며, reason에는 이유를 적는다.

```bash
python3 automation/request_verification.py --source <40자리-work-head-SHA> --reason '<전체검사가 필요한 이유>'
```

- 생성되는 `automation/verification-request.json`을 변경물과 함께 commit한다. 실제 검증 대상은 그 요청을 포함한 CI의 HEAD이며 후보에도 source SHA가 기록된다. 이미 같은 소스·도구·설정에서 성공한 검사는 이유 없이 다시 요청하지 않는다.
- 두 트리거는 검증만 시작한다. 버전 없는 수정에 임의 버전/패치를 만들지 않는다.
- 실패하면 원인과 실제 실패 구간부터 확인한다. 영향 없는 통과 결과를 재사용하려면 소스·도구·설정·빌드입력·테스트 데이터 준비의 동일성과 성공 증거를 먼저 기록한다. 일반화된 안전한 재개가 준비되지 않았다면 임시 스킵을 즉석으로 덧붙이지 않는다.
- v1.37 한 건에 고정됐던 자동 재개는 이력으로 옮겼다. 새 정상 검사는 초기 import→관련 렌더→전체 검사/격리 재접속→나머지 렌더→PCK 순서로 모두 실행한다.

## 공개와 기록

- 성공한 입력 fingerprint·버전·소스·도구가 일치하는 후보만, 새 공개 승인 범위에서 main에 반영한다. 검사 완료 파일을 다시 빌드하지 않는다.
- 공개3파일·전체소스·운영 다운로드의 크기/해시·부분 다운로드 검증은 유지한다. 휴대폰 실기 적용은 별도 확인이다.
- `evidence/ci-timings.json`과 `.md`, Actions 요약에 단계별 소요 시간을 남긴다. 진행 중 단계와 대기열은 완료 시간에 포함되지 않는다. 계측 실패는 검사 성공으로 둔갑시키지 않으며 메타데이터 실패로 표시한다.
- 이 개선 자체로 실제 단축 시간을 보장하지 않는다. 다음 승인 배포 결과에서 병목과 시간을 비교한다.
- 이번 변경은 work/*에서 준비하며 현재 공개 v1.37/게임/세이브/아트/밸런스는 바꾸지 않는다. 이 도구 변경만 main으로 병합하면 기존 공개 workflow가 동작할 수 있으므로, 다음 승인된 게임 배포에 검증된 도구 변경을 함께 반영한다.
