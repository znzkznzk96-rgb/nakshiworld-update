# 새 채팅용 낚시월드 즉시 이어하기

이 저장소가 프로젝트 인수인계의 기준이다. 사용자에게 예전 설명이나 ZIP 재첨부를 요구하지 말고 GitHub의 최신 파일과 Release를 직접 읽는다. 사용자 첨부는 근거 확인에 꼭 필요하고 저장소에도 없는 파일이 실제로 누락됐을 때만 요청한다.

## 새 작업을 시작할 때

1. `START_HERE.md`, `AGENTS.md`, `docs/PROJECT_INSTRUCTIONS.md`를 읽는다.
2. `docs/GAME_BIBLE.md`에서 확정/미정 결정을 읽는다.
3. `WORK_STATE.json`의 `work_branch`, `current_task`, `next_step`를 읽고 해당 원격 브랜치의 최신 `HANDOFF.md`를 확인한다. 브랜치가 여러 개면 담당 작업/최근 갱신/상태를 비교한다. 가장 높은 버전 번호만 보고 최신 작업을 추측하지 않는다.
4. `CHANGELOG.md`, 실제 GitHub Release와 현재 실행 중인 workflow 조건을 확인한다. 기획 문서·구현·배포·휴대폰 확인은 각각 구분한다.
5. 게임 파일 수정 전 공개 최신 `game-source.zip`을 기준으로 해당 작업 브랜치 overlay 및 삭제/이름 변경을 확인한다. `game/`만 전체 프로젝트라고 가정하지 않는다.
6. 기존 기획에서 사용자가 이미 정한 내용을 확인한 뒤에만 부족한 결정을 질문한다. 이미 답을 얻은 것을 다시 묻지 않는다. 서로 무관한 질문을 여러 차례 나눠 묻지 말고 필요한 미정 항목을 한 번에 묶는다.

## 저장/연속성 규칙

- 사용자가 새로 확정하거나 바꾼 게임 결정을 받으면 코드 수정이 없어도 같은 작업에서 즉시 `docs/GAME_BIBLE.md`에 날짜·상태·근거와 함께 기록한다. 관련 구현을 시작하기 전에 `GAME_BIBLE.md`·변경물·`HANDOFF.md`·`WORK_STATE.json`을 `work/*`에 원격 저장하고 새 SHA 및 파일 내용을 재확인한다. 한 메시지의 여러 결정은 한 checkpoint로 묶는다.
- 원격 저장이 전부 실패한 경우 해당 결정을 미저장 대기로 표시하고 사용자에게 정확히 알린다. 다음 채팅에서 저장된 것처럼 행동하거나 사용자에게 같은 설명을 다시 요구하지 않는다.

- 의미 있는 진행마다 변경물과 `HANDOFF.md`, `WORK_STATE.json`을 같은 `work/*` 커밋으로 저장하고 원격 커밋 SHA를 다시 읽어 검증한다.
- 원격 저장 성공 전에는 “저장됐다/다른 채팅에서 이어진다”고 말하지 않는다. push가 실패하면 로컬 커밋과 원인을 즉시 기록하고, 동일 저장소 API 등 허용된 원격 경로를 시도한다. 그래도 실패할 때만 사용자에게 필요한 조치와 구체 파일을 알린다.
- 배포 브랜치(main/codex/r2-migration)에 미완성 게임 변경을 저장하지 않는다. 배포 동작은 workflow를 다시 확인한다.
- 작업 결정, 테스트, 남은 일, 실패와 실제 원격 위치를 `HANDOFF.md`에 남긴다. `WORK_STATE.json`은 현재 진행 중인 단일 작업을 간결히 가리키게 유지한다.
- 게임에 대한 지속성 있는 결정은 코드 주석만이 아니라 `docs/GAME_BIBLE.md`에 기록한다. 게임 소스·PCK와 기획 기준 문서를 분리한다.
- 과거 채팅 전체가 자동 복구된다고 주장하지 않는다. 확정사항·근거·불확실성을 분리하고 자료가 없는 부분은 미정으로 둔다.
- 사용자가 이미 승인한 범위 내 수정은 진행한다. 배포/외부 공개는 실제 사용자 지시와 안전한 검증을 지킨다.

## 지금 이어갈 작업

활성 작업은 `WORK_STATE.json`이 지정한다. 2026-10-22 계곡 결정은 `GAME_BIBLE.md`의 날짜별 표와 계곡 섹션이 기준이다. 현재 선택한 배경·물고기 20종의 실제 등록/원격 보존 여부는 최신 작업 HANDOFF와 원격 파일 존재를 확인해서 판단한다. 로컬 환경에서만 완료된 결과를 원격 저장된 것으로 보고하지 않는다.

## 사용자가 새 채팅에 보낼 한 줄

`낚시월드 이어서 하자. GitHub 최신 START_HERE.md와 docs/CONTINUE_HERE.md부터 읽고, WORK_STATE.json이 가리키는 작업을 그대로 이어가. GAME_BIBLE.md의 확정사항은 다시 묻지 말고, 원격 상태를 확인한 뒤 진행 상황만 짧게 알려줘.`
