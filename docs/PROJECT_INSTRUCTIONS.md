# 낚시월드 프로젝트 작업 지침

이 문서는 새 대화·작업 환경에서도 같은 기준으로 낚시월드 개발을 이어가기 위한 상위 지침이다. 사용자가 이 문서를 직접 바꾸면 최신 요청을 반영한다.

## 프로젝트와 기록의 원본

- 프로젝트는 Godot 4.4.1 안드로이드 세로형 도트 낚시게임 **낚시월드**다. 한국어로 간결히 답하고 승인된 작업은 직접 수행한다.
- 게임 결정의 원본은 코드 밖 `docs/GAME_BIBLE.md`, 다음 채팅 절차는 `docs/CONTINUE_HERE.md`, 작업 진행은 `HANDOFF.md`와 `WORK_STATE.json`, 변경 이력은 `CHANGELOG.md`다.
- 시작할 때 최신 GitHub `START_HERE.md`, `AGENTS.md`, 이 문서, `docs/CONTINUE_HERE.md`, `docs/GAME_BIBLE.md`, `HANDOFF.md`, `WORK_STATE.json`, `CHANGELOG.md`를 읽는다. 진행 중인 작업 브랜치와 실제 최신 GitHub Release/Actions도 확인한다.
- 문서와 코드가 다르면 최신 사용자 명시 결정을 기획 기준으로 삼고, 실제 구현 여부는 최신 코드와 테스트로 확인한다. 이전 결정과 충돌하면 새 결정을 날짜·근거와 함께 바이블에 기록하고 이전 것은 폐기/대체로 남긴다.
- 이미 문서나 과거 기록에서 답을 찾을 수 있는 사항을 사용자에게 되묻지 않는다. 자료를 저장소·Release·작업 브랜치에서 먼저 찾는다. 필요한 결정이 정말 없다면 서로 관련된 미정 사항을 한 번에 묻고, 사용자 승인 전 임의로 확정하지 않는다.
- 첨부 ZIP은 초기 복구 자료일 수 있으므로 최신 프로젝트로 가정하지 않는다. 최신 전체 게임 소스는 실제 최신 Release의 `game-source.zip`이다. 저장소 `game/`은 overlay이며 전체 프로젝트가 아니다.

## 작업·저장·배포

- 요청 범위를 지키고 승인되지 않은 그림, UI, 밸런스, 스토리, 경제를 바꾸지 않는다. 기존 세이브를 보호하고 앱 삭제나 데이터 초기화를 기본 해결책으로 쓰지 않는다.
- 의미 있는 단계마다 코드/리소스와 `HANDOFF.md`, `WORK_STATE.json`을 작업 브랜치 `work/*`에 함께 저장한다. 시작 전 최신 workflow의 실제 배포 조건을 확인하고, 배포 브랜치에 미완성 게임 변경을 넣지 않는다.
- Git CLI push가 실패하면 허용된 GitHub 연결/API를 확인해 저장을 이어간다. 원격 커밋 SHA를 재조회하기 전에는 원격 저장 완료라고 말하지 않는다. 모든 원격 경로가 실패하면 로컬에만 남은 정확한 결과와 원인을 알린다.
- HANDOFF에는 완료/미완료, 실패, 테스트, 남은 문제, 다음 작업과 배포 상태를 남긴다. 바이블에는 지속될 결정만 남기며 코드 구현과 혼동하지 않는다. WORK_STATE는 지금 이어갈 작업 하나를 가리킨다.
- 작업 중, 검증 완료, 공개 배포, 휴대폰 적용 확인은 별개다. 배포는 사용자 지시가 있을 때만 한다. 배포 시 Release의 전체 소스 ZIP·PCK·`version.json`·커밋·크기·해시를 검증하고 기록한다. 다운로드 성공만으로 휴대폰 적용 성공이라 하지 않는다.
- 토큰·비밀번호·서명키·키스토어·실사용자 세이브를 커밋하지 않는다. 자동검사는 별도 테스트 데이터에서 실행한다.
- 원문 채팅 전체가 새 대화로 자동 이동한다고 주장하지 않는다. 확정된 결정과 인수인계를 이 저장소에 계속 기록해 재설명을 없앤다.

## 그림과 물고기

- 낚시터 물고기 이미지 제작 전 `docs/FISH_ART_RULES.md`를 읽는다. 승인된 외형 시안과 게임 내 저수지 원본의 색감·도트·명암 기준을 각각 따른다. 외형 승인만으로 색감까지 승인된 것으로 해석하지 않는다.
- 유료 생성은 사용자가 승인한 범위에서만 한다. 어종별 형태·주조색·보조색·강조색·필수 특징과 적합한 참조를 먼저 기록한다. 한 종 생성 후 실제 저수지 물고기와 비교 검수하고 통과해야 다음 종으로 간다. 동시 유료 요청 1개 이하, 자동 재시도 금지. 부적합하면 즉시 중단하고 실제 비용·요청·결과를 기록한다.
- 임시 컬러 시안을 초기/스타일/색 참조로 재사용하지 않는다. 금빛 붕어 한 종을 공통 강참조로 돌리지 않는다. 투명도·잘림·원본 및 정수 확대의 픽셀 품질도 확인한다.
- **계곡 아트 상태를 혼동하지 않는다:** 최초 색감 거절본 20종은 실패 기록이며 사용 금지. 이후 확정 모음의 20종과 사용자가 선택한 상세 배경은 디자인 선택본이다. 이 선택이 고해상도 재제작이나 게임 연결·검수·배포 완료를 뜻하지 않는다. 현재 정확한 에셋·진행 상태는 바이블/핸드오프/원격 파일에서 확인한다. 새 유료 생성이나 배경 대체를 하지 않는다.

## 현재 계곡 작업 기준

반드시 `docs/GAME_BIBLE.md`의 최신 계곡 기록을 따른다. 핵심은 박물관 메인 번들 완료 → 급수 자격증 및 다음 낚시터 구매 자격 → 별도 비늘 지불로 입장, 번들 어종 조건은 사용자가 정할 때까지 준비 중, 해당 낚시터 파츠 4개 장착 후 주인 게이지 누적/100% 다음 물고기 출현/실패70%/포획0%, 계곡 20종 평균 및 종별 최대 길이다. 상충하는 오래된 수치나 추천안을 복사하지 않는다.
