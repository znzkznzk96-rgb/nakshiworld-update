# 프로젝트 지침 교체용

아래 코드 블록 전체로 기존 지침을 교체한다. 현재 게임 상태는 하드코딩하지 않고 최신 저장소에서 읽는다.

```text
이 프로젝트는 Godot 4.4.1 안드로이드 세로형 도트 낚시게임 ‘낚시월드’다. 한국어로 간결히 답하고 승인된 작업은 직접 수행한다.

저장소: https://github.com/znzkznzk96-rgb/nakshiworld-update

[최신 상태와 이어가기]
새 작업은 최신 START_HERE.md → docs/CONTINUE_HERE.md 순서로 시작한다. AGENTS.md와 docs/PROJECT_INSTRUCTIONS.md를 따르고 WORK_STATE.json이 가리키는 원격 브랜치의 최신 HANDOFF·WORK_STATE, docs/GAME_BIBLE.md, CHANGELOG 최신 항목, 실제 Release·관련 Actions·배포 workflow를 확인한다. 같은 세션에서 읽은 자료는 SHA/관련 diff가 바뀐 부분만 다시 확인한다. 과거 이력/모든 브랜치는 필요할 때만 조사한다.
첨부 ZIP은 초기 복구 자료다. 게임 수정은 최신 Release game-source.zip + 작업 브랜치 overlay/삭제 명세를 기준으로 한다. game/만 전체 프로젝트로 가정하지 않는다. 검증된 소스·도구·import 캐시는 기준이 맞으면 재사용한다. 문서 작업에 게임 복원/빌드를 하지 않는다.

[결정과 기록]
GAME_BIBLE는 확정·미정·폐기 기획과 변경 근거, WORK_STATE는 활성 작업/다음 단계, HANDOFF는 현재 상세 인수인계, CHANGELOG는 변경 결과를 기록한다. 상세 로그/해시는 검증 문서에 두고 링크한다. 동일 상태를 여러 문서에 복사하지 않는다. 과거 문서는 원문/근거를 이력에 보존한다.
새 게임 결정은 코드 변경이 없어도 즉시 날짜·근거·상태와 함께 GAME_BIBLE에 기록한다. 그 결정에 의존하는 구현 전 관련 변경물·HANDOFF·WORK_STATE와 함께 work/*에 원격 저장하고 SHA/내용을 확인한다. 같은 메시지의 결정은 묶어도 된다. 단순 진행도 의미 있는 단계마다 저장하며 종료 때까지 미루지 않는다. 확정사항 재질문·불필요한 재첨부 요구를 하지 않는다. 원문 채팅 전체나 미저장 작업의 자동 복구를 약속하지 않는다.

[속도와 검증]
필요한 수정→영향 범위 검사→결과 표시→원격 checkpoint로 진행하되 새 결정 즉시 저장이 우선한다. 화면 결과는 준비되는 즉시 보여주고 검증/저장/배포 상태를 구분한다. 60초 이상 진행 설명 없이 기다리게 하지 않는다.
개발 중 관련 검사, 세이브·공통 시스템 변경 및 배포 전 필수 전체 검사를 수행한다. 같은 소스/도구/설정의 통과 검사는 변경·실패·미해결 의심 없이 반복하지 않는다. 문서 변경은 링크·JSON·이력 보존·diff·트리거만 확인한다. 독립 작업은 묶어 처리하되 공유 테스트 데이터는 분리한다.
이미 작동한 원격 저장 경로를 먼저 사용한다. 이 환경에서 인증 실패한 Git push를 반복하지 말고 GitHub API를 사용한다. 원격 head/expected SHA로 다른 변경을 보호한다. 모든 저장 경로 실패 시 로컬에만 남은 결과를 정확히 알린다.

[배포와 보호]
중간 작업은 work/*에 저장하고 현재 자동 배포 조건을 확인한다. 문서만 수정하면 게임 버전/패치를 만들지 않는다. 기존 배포 승인을 이후 새 패치의 포괄 승인으로 해석하지 않는다. 배포 요청 시 소스 커밋·버전·전체소스ZIP·PCK·version.json의 실제 존재/크기/해시와 운영 다운로드를 확인해 기록한다. 수정/검증/배포/휴대폰 적용은 구분한다.
승인 UI·아트·밸런스를 임의 변경하지 않는다. 미정 조건은 준비 중. 기존 세이브 보호와 격리 테스트를 지키고 앱 삭제/데이터 초기화를 기본 해결책으로 삼지 않는다. historical 소스를 최신에 덮지 않는다. 토큰·비밀번호·서명키·실사용자 세이브를 공개하지 않는다.

[물고기 아트와 유료 생성]
제작 전 docs/FISH_ART_RULES.md 전체를 읽고 전 낚시터에 적용한다. 외형은 승인 시안, 색감·명암·도트는 실제 저수지 원본20종 기준이다. 외형/색감 승인은 별개다. 어종별 형태·주/보조/강조색·명암·필수 특징·참조 역할/선정 이유를 먼저 명세한다. 흐림·물빠진 색·회색/누런 막·의도하지 않은 저채도, 전종 금빛 통일을 피한다.
임시 컬러 시안/잘라낸 이미지를 초기·스타일·색 입력으로 사용하지 않는다. 형태 전용 자료는 색/배경을 분리해 실제 입력을 검토하며 흑백 변환만으로 해결됐다고 가정하지 않는다. 어종에 적합한 저수지 원본을 고르고 금빛 붕어 공통 강참조를 쓰지 않는다. 실제 요청 설정/전송 이미지를 확인한다.
승인 횟수 내 어종별1장 기본. 첫1종 생성→원본 크기와 nearest 정수 확대 비교 검수→통과 후 다음 종. 동시 유료요청 최대1개. 형태/색/명암/윤곽/특징/투명/잘림과 품질 통과를 기록한다. 부적합 즉시 후속 호출 중단. 병렬·대량 예약·자동 재시도·승인 없는 추가 생성 금지. 타임아웃 시 과금/작업ID/기존 결과부터 확인한다. 설정·모델·seed·참조/결과 해시·실제 차감·검수결과를 비밀키 없이 보존한다.
최초 거절20종은 임시 컬러와 공통 금빛 참조로 문제를 확인하고도 계속해20회 차감한 실패 기록이다. 이후 최종 선택20종과 구분하고 승인 참조/적용본/성공 사례로 재사용하지 않는다. 최신 사용자 변경 지시가 우선한다.
```
