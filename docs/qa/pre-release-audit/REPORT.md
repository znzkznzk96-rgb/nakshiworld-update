# 배포 전 누락 점검

검사 대상: work/valley-runtime `0f931337efab1f5e29e8499204ab88ed1186135b`. 운영 0.76과 구분한다. 이번 작업은 감사 및 증거 보존이며 게임 수정·공개 배포를 하지 않았다.

## 결론

이미지 원본의 추가 유실은 확인되지 않았으나 **원본 모션의 실제 재생 연결과 표시 정보가 빠져 있다.** 기존 기능 검사 통과를 시각적 완성 또는 모든 프레임 연결 완료로 해석하면 안 된다.

| 우선 | 확인된 항목 | 근거 및 영향 | 다음 수정 |
|---|---|---|---|
| 높음 | 보스 4종의 대기·피격 프레임 미연결 | 각 24칸 중 대기 1칸, 피격 1칸, 공격 6칸, 사망 6칸만 도달 가능. 합계 96칸 중 40칸 미사용. `animation_probe.gd`가 실제 battle_art 호출을 표본 검사함. 원본 시트는 온전함. | 원본 대기·피격 시퀀스 모두 연결하고 실제 전투 영상 확인. |
| 높음 | 병사 피격·퇴장 연출 미구현 | `view.gd:battle_art`는 HP가 0 이하면 바로 continue. 실제 그리기 호출도 즉시 사라짐. 피해를 받은 병사의 별도 반응도 없음. 병사 원본은 기본+대표액션이므로 별도 HIT/DEATH 이미지가 유실된 것은 아님. | 기존 스프라이트를 이용한 피격·자연스러운 퇴장 연출 구현. |
| 중간 | 3성 희귀도 목록 표시 누락 | 희귀도는 저장·수치 보정·결과창에 존재하나 병사 목록, 합성 재료 목록, 편성 선택 목록에는 표시하지 않음. 결과창을 닫으면 레어/유니크/전설 구분을 확인하기 어려움. | 목록과 편성에서 별 등급과 별도로 희귀도 표시. 저장 데이터는 변경할 필요 없음. |
| 중간 | 지원 행동의 시각적 구분 부족 | 모델은 매 3번째 틱에 회복·보호를 처리하지만 화면은 공통 전투 시계로 대표액션을 반복함. 대상에게 회복·지원이 발동한 순간의 표시가 없으며 실드 원호만 존재. | 실제 발동 틱·대상에 맞춰 지원 효과 표시. 새 복잡한 스킬 설계는 불필요. |
| 별도 APK | 선택된 B안 업데이트 화면 미반영 | WORK_STATE.update_screen은 approved=true/game_applied=false. 실제 root.gd는 단색 배경·문자·노란 막대. 시안/개선 소스는 docs/proposals에 보존됨. | B안 로더를 실제 APK에 적용해야 함. 이미 설치된 APK의 root는 PCK 마운트 이전 실행되므로 PCK만 배포해서는 교체되지 않음. |

추가 표시 차이: 마을 탐험 퍼센트는 적 처치 수 기준 0/33/66으로만 바뀐다. 시안의 42% 같은 세밀한 진행 표시와 다르다. 현재 구현 방식에 대한 확인 사항이며, 확정된 연속 진행률 규칙이 누락됐다고 단정하지 않는다.

## 보존 및 연결 확인

- 공개 0.76 전체 소스 ZIP에서 새 디렉터리를 복구하고 최신 work 파일을 덮은 뒤 승인 원본 아카이브의 해시/ZIP CRC/병사 개별 프레임 해시를 검증했다.
- 탐험 PNG 151개: 일반 18종×7자세=126개, 보스 시트 4개, 병사 시트 15개, 어혼 5개, 석궁 투사체 1개. 모두 정상 로드된다.
- UI 원본 3장 해시 일치. 6개 메뉴와 순차 등장, 10개 방 카드/배경, 3·5·7R 해골 및 10R 왕관 해골, 연성·편성 화면은 직전 UI 수정본에 연결돼 있다. 해당 수정본은 아직 미배포다.
- 0.76 기준 이미지·음원·폰트 866개가 바이트 동일. 바뀐 기존 미디어 0개. 삭제된 것은 원본 아이콘으로 대체한 임의 SVG 2개뿐이다.
- 일반 HIT 18종의 전체 이미지 경계는 완전 투명이며 승인된 정리본과 일치한다. 이것만으로 모든 내부 픽셀에 대한 육안 검수까지 대체하지는 않는다.
- 병사 15종의 ID/조합/역할/프레임 크기/131개 타임라인 프레임 수가 원본 명세와 일치한다. 131개가 전부 다른 포즈라는 뜻은 아니다.
- 15개 조합, 병사 1·2·3성 체력/공격력/방어력, 몬스터 22종 수치, 10개 라운드가 존재한다. 일반 18종 모두 라운드에 등장하며 각 라운드 3마리, 일반 중복 최대 2마리, 3·5·7·10R 마지막 보스 조건을 만족한다.
- 10R은 수정된 320px 시트와 1200HP/80공격/40방어를 사용한다. 대기 프레임의 투명 여백을 제외한 실제 미니 표시 높이는 약 27.5, 7R은 22.3(논리 화면 단위)로 10R이 더 크다. 구형 작은 시트가 잘못 들어간 것은 아니다. 위압감의 충분함은 별도 시각 판단이다.
- 개체값·합성 계승·희귀도는 저장 데이터에 남는다. pending 합성/보상 중복 방지, 기존 낚시 저장 호환, 회복 대기 검사는 통과했다.
- 실제 750개 조합 전투: 전원 1성 0/125, 2성 1마리 7/375, 2성 방어+공격 102/125, 전원 2성 125/125 승리. 2성 두 마리 중심 목표 수치는 유지된다.
- 새로 만든 감사용 PCK에서도 병사/일반몹/보스/어혼/UI 원본 3장과 기존 고양이/캐릭터/낚싯대/마을 BGM이 로드된다. 공개 배포하지 않은 로컬 검사 파일이다.

## 구분한 과거 기록과 한계

과거 고양이 검토 후보, 경제 시뮬레이션 후보, 단계별 해금 가격 이전의 단일 가격 제안, 복잡한 상성표와 구형 병사 설계는 최신 결정으로 대체되었거나 미확정이다. 이를 현재 누락으로 잘못 계산하지 않았다. 계곡 실제 입장 비활성도 기존 유지 범위다.

이번 검사는 저장소의 확정 기록·첨부 원본·복구 가능한 승인 아카이브와 현재 코드를 기준으로 한다. 과거 대화에만 있었고 기록/파일이 남아 있지 않은 별도 시안까지 존재하지 않는다고 보증하지 않는다. Android 실제 기기에서 전 장면·터치·모션을 재검수한 것은 아니다. 기능 회귀 30개와 패킹 검사는 모션 연결 누락을 잡지 못했으므로 프레임 도달성 검사를 별도로 추가했다.

증거: `assets.json`, `animation.json`, `tests.json`, `packed-art.log`, `asset_audit.py`, `animation_probe.gd`.
