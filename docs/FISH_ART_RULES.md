# 낚시월드 물고기 아트 제작 규칙

2026-10-21 사용자 지시 반영. 거꾸로 폭포 계곡 재작업 및 이후 남은4개 낚시터 전체에 적용한다. 사용자의 이후 명시 변경은 이 문서보다 우선한다.

## 고정 기준
- 외형: 사용자가 승인한 시안의 체형, 지느러미, 꼬리, 무늬 위치, 이상현상 특징을 따른다.
- 색감·분위기·도트: 실제 게임의 저수지 원본20종이 기준이다. 임시 시안의 색/배경/질감을 승인된 색감으로 해석하지 않는다.
- 물 빠진 색, 회색·누런 막, 의도하지 않은 저채도, 흐림을 금지한다. 어종마다 주조색·보조색·강조색과 밝음/중간/어두움의 구분을 정한다. 모든 물고기를 금빛으로 통일하거나 무조건 채도만 올리지 않는다.
- 선명한 눈/윤곽/비늘, 깔끔한 픽셀 묶음, 기존 저수지와 일관된 명암을 유지한다. 잔점·디더링이 원본보다 과해 형태를 흐리면 실패다.
- 물방울·잎 꼬리·이끼·구름·붉은 반점 등 종별 핵심 특징은 작은 게임 표시 크기에서도 읽혀야 한다.

## 참고 이미지와 API 입력 분리
1. 임시 시안은 눈으로 외형을 분석하고 어종별 형태 명세로 옮긴다. 임시 시안의 원본/잘라낸 컬러 이미지를 init_image, style_image, color_image 또는 다른 이름의 시각 입력으로 그대로 넣지 않는다.
2. 외형 유도 입력이 필요하면 색과 종이 배경을 제거한 형태 전용 자료를 별도로 만들고, 실제 전송할 자료를 직접 확인한다. 단순 흑백 변환만으로 배경·질감 전이가 사라졌다고 가정하지 않는다. 형태 전용 입력도 기능과 영향이 확인된 경우에만 쓴다.
3. 스타일 참조는 실제 저수지 원본 중 해당 어종의 목표색·체형에 적합한 것을 선정한다. 금빛 붕어1장을 전 어종 공통 강한 참조로 재사용하지 않는다. 각 선택 이유/경로/해시를 기록한다.
4. 모델이 외형과 색/스타일 참조를 분리할 수 있는지 현재 API 문서로 확인한다. 분리가 보장되지 않는 기능에 기대어 대량 생성하지 않는다. '선명하게'라는 프롬프트만으로 색 통제가 됐다고 간주하지 않는다.
5. 요청 직전 실제 JSON과 모든 시각 입력을 검사한다. 계획과 다른 임시 시안이나 과거 금색 참조가 코드에 남아 있으면 호출하지 않는다.

## 유료 생성 절차
- 어종별로 이름/확정 외형/핵심 특징/주·보조·강조색/금지색/참조 역할/해상도/예상 호출 수를 먼저 문서화한다. 등급이 높다는 이유로 무조건 크게/금빛으로 바꾸지 않는다. 크기·밸런스는 별도 승인 사항이다.
- 첫1종을 생성한 뒤 아래 품질 기준을 확인한다. 첫 결과가 틀리면 후속 호출을 중단하고 설정을 재검토한다. 요청이20종이어도20종 선예약·병렬 큐로 검수 기회를 없애지 않는다.
- 이후도 한 종 생성→검수→다음 종 순서. 요청 중인 유료 생성은 최대1개. 미리보기 후보를 여러 장 뽑지 않는다. 단일 결과1장 요청 여부를 확인한다.
- 각 결과를 저수지 비교 원본과 나란히 원본 크기 및 nearest 정수 확대에서 본다. 형태/고유색/명암/윤곽/특징/알파/잘림 각각 pass 또는 fail과 근거를 기록한다. PNG 저장 성공은 품질 통과가 아니다.
- 핵심 항목 하나라도 fail이면 다음 유료 호출을 멈춘다. '나중에 고칠 것'이라고 메모만 남기고 나머지를 생성하지 않는다. 결과를 공유하고 실패 원인과 구체적인 수정안을 정리한다.
- 명시한 어종당1회 제한을 임의 초과하지 않는다. 실패·타임아웃 시 과금/작업ID/저장 결과를 조회하고 자동 재시도하지 않는다. 추가 비용이 필요한 재생성은 사용자 허용 범위 안에서만 한다.
- 실제 차감량을 기록한다. 요청/응답 메타, seed, 모델, 참조 경로·해시, 결과 해시, 검수, 성공/실패/중단 상태를 비밀키 없이 보존한다.

## 저장과 적용
work/* 브랜치에 원본·검수·HANDOFF·WORK_STATE를 함께 저장하고 원격 SHA를 확인한다. rejected 결과는 참고용/실패 기록일 뿐 후속 생성의 스타일 기준이나 게임 적용본이 아니다. 원본 유지, 별도 수정본 구분. 배포는 별도 요청 범위를 따른다.

## 이번 실패 기록 — 관측과 추정 구분
실제 실행: 승인한 임시 시안을 잘라 init_image_strength450으로 입력하고, 금빛 저수지 붕어 l0_01.png를20종 공통 style_image/style_strength65로 사용했다. create-image-bitforge,96×64,2개 병렬 생성. 금빛 과다와 특징 손실을 확인하고도18종 후속 생성을 계속했다. 총20회 차감. 게임에는 적용하지 않았다.
관측: 사용자가 색감 부적합으로 결과를 거절했다. 일부 어종의 고유색/물방울/구름/붉은 무늬가 약해졌다.
추정: 임시 시안의 탁한 색과 공통 금빛 참조가 결과에 영향을 줬을 가능성이 높다. 각 설정의 기여도는 통제 비교로 검증하지 않았으므로 단정하지 않는다.
운영 실패: 이미 반복된 사용자 요구를 실제 입력 및 중간 검수에서 지키지 않았고, 비용 발생을 멈출 수 있었는데 계속했다. 이후 에이전트는 이를 사용자 승인 아트 또는 성공 사례로 재사용하면 안 된다.
