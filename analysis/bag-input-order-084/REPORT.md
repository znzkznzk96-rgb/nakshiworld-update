# 가방 입력 잠금 재현·수정 — 2026-10-27 KST (미배포)

## 원인
Godot 4.4.1 `core/input/input.cpp`의 `_parse_input_event_impl`은 ScreenTouch를 처리하면서 생성한 가상 MouseButton(device=-1)을 먼저 재귀적으로 전달한 뒤 원래 ScreenTouch를 전달한다.
출처: https://github.com/godotengine/godot/blob/4.4.1-stable/core/input/input.cpp

기존 가방은 마지막 네이티브 터치 이후 500ms 동안만 가상 마우스를 무시했다. 그보다 오래 쉰 뒤 첫 탭에서 가상 mouse-down이 pointer_id=-1을 선점하고, 뒤따르는 native-down은 이미 pointer=true라 무시된다. native-up은 id=0이라 해제하지 못하고 가상 mouse-up은 새로 갱신된 시간 제한 때문에 무시된다. 따라서 탭을 끝내도 포인터가 눌린 상태에 남아 물고기 선택/상세 닫기/가방 닫기가 막힌다. 기존 2초 stale-pointer 복구에 의존해 수 초 뒤 풀릴 수 있었다.

기존 회귀검사는 native-down을 먼저 수동 전달하여 실제 엔진 순서와 달랐다. 이전 데스크톱 프레임 지연 측정은 입력 잠금 재현 검사가 아니었으므로 이 문제를 배제하지 못했다.

## 수정
가방/물고기 상세가 입력을 소유할 때는 가상 마우스를 시간 조건 없이 무시하고 네이티브 터치로 처리한다. 실제 마우스(device=0)와 휠은 유지한다. 닫은 직후 다른 UI로 관통하는 가상 이벤트 억제는 유지한다. 메뉴의 가상 mouse-down으로 가방이 열린 같은 제스처는 첫 레이아웃 이전에 가방 클릭으로 재해석하지 않는다.

이전 미배포 글자크기 애니메이션 제거/뒤·중간·앞/PixelLab 아이콘/배치스크롤은 보존. 추가 UI/밸런스/세이브 형식 변경 없음.
